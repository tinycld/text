## What "Save version" does

Your document auto-saves continuously — changes go to Drive within seconds. **Save version** is different: it lets you stamp a named checkpoint into the document's history so you can return to a specific moment, like "before the editor's pass" or "shipped draft."

## Saving a version

1. Open the document.
2. Choose **File → Save version**.
3. Add a short description (optional but recommended — empty submits a timestamp). The description can be up to 500 characters.
4. Click **Save**.

The new version appears in the document's version history. The current file isn't modified — saving a version is a snapshot, not a save-as.

## Seeing and restoring versions

1. Choose **File → Version history**.
2. Click a version in the list to preview it. Your document does not change.
3. Click **Rename** to change the version's label, or **Restore** to make it the current document.

A restore keeps the history: the state you replace stays in the list, and a "Restored from …" version is added. If the document is open in an editor, it first saves its last edits, which stay in the list as a version. Then every open editor reloads with the restored contents.

See [Drive versions](help://drive:versions) for more on managing version history.

Automatic versions are off unless your organization turns them on. To turn them on or off for this document, choose **File → Automatically version while editing**. A check mark shows they are on. See [Version history](help://drive:versions).

## When to save a version

- Before a major rewrite or before deleting sections you might want back.
- At a milestone you'd want to reference later (a draft you sent for review).
- Before importing or pasting a large block of new content.
- Before applying a template that restructures the document.
